### Интеграция с `clasp` и раздельное развертывание

Проект использует сложную систему развертывания с `clasp`, которая разделяет клиентскую и серверную части приложения на два независимых проекта Google Apps Script. Это позволяет управлять ими отдельно, что повышает надежность и упрощает разработку.

#### 1. Ключевые файлы

-   **`.clasp-client.json`**: Конфигурационный файл `clasp` для **клиентской** части. Содержит `scriptId` и `rootDir` для фронтенда.
-   **`.clasp-server.json`**: Конфигурационный файл `clasp` для **серверной** части. Содержит `scriptId` и `rootDir` для бэкенда.
-   **`.claspignore-client`**: Список файлов и папок, которые игнорируются при развертывании **клиента**. Это предотвращает попадание серверного кода в клиентский проект.
-   **`.claspignore-server`**: Аналогичный файл для **сервера**, который исключает клиентские файлы.
-   **`deploy-to-folder.js`**: Главный скрипт, который, по всей видимости, управляет процессом развертывания. Он, вероятно, переключается между `.clasp-client.json` и `.clasp-server.json` для развертывания соответствующей части.
-   **`clean-client-project.js`**: Скрипт-утилита, который, вероятно, очищает или подготавливает директорию с клиентским кодом перед развертыванием.
-   **`.deployment-trigger`**: Файл-флаг. Его наличие, скорее всего, является сигналом для CI/CD системы о необходимости запустить процесс развертывания.

#### 2. Процесс развертывания

Хотя точная реализация находится в `deploy-to-folder.js`, можно предположить следующий алгоритм:

1.  **Триггер**: Процесс инициируется наличием файла `.deployment-trigger` или вручную.
2.  **Очистка**: Запускается `clean-client-project.js` для подготовки клиентской директории.
3.  **Развертывание клиента**:
    -   Скрипт `deploy-to-folder.js` использует `.clasp-client.json` в качестве основного конфига `clasp`.
    -   Выполняется команда `clasp push` (или аналогичная), которая загружает только файлы, разрешенные в `.claspignore-client`.
4.  **Развертывание сервера**:
    -   Скрипт `deploy-to-folder.js` переключается на `.clasp-server.json`.
    -   Выполняется команда `clasp push`, загружая только файлы, разрешенные в `.claspignore-server`.
5.  **Мониторинг**: Скрипт `monitor-workflow.sh` может использоваться в CI/CD для отслеживания статуса и логов этого процесса.

Эта архитектура обеспечивает четкое разделение между клиентским и серверным кодом, что является лучшей практикой для крупных проектов Apps Script.
