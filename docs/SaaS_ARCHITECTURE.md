# 🏗️ Архитектура Table AI SaaS (Shell + Brain)

Система построена на принципе разделения статической оболочки и облачного интеллекта.

## 1. Компоненты системы

### 🐚 Оболочка (Shell) — `klublocal.ddns.net`
- **Frontend:** React 19 + Vite. Собран в `web/dist`.
- **Web Server:** Nginx 1.24.
- **Роль:** Отдача статики пользователю и безопасное проксирование API-запросов.
- **Nginx Config:** Настроен на `proxy_pass` для пути `/api` в сторону Cloudflare.

### 🧠 Мозг (Brain) — Cloudflare Workers
- **Worker:** `table-ai-backend`.
- **Database:** Cloudflare D1 (SQLite-compatible).
- **Роль:** Вся бизнес-логика, авторизация, обработка AI-запросов и хранение данных.
- **Преимущество:** Бесконечная масштабируемость и высокая доступность.

## 2. Поток авторизации (VK OAuth)

1. Пользователь нажимает «Войти ВК» на `klublocal.ddns.net`.
2. Запрос уходит на `klublocal.ddns.net/api/auth/vk/login`.
3. Nginx прозрачно проксирует это в Cloudflare.
4. Worker генерирует URL авторизации с `redirect_uri=https://klublocal.ddns.net/api/auth/vk/callback`.
5. ВК возвращает пользователя на ваш домен.
6. Nginx снова проксирует ответ в Worker.
7. Worker выдает JWT и редиректит на `klublocal.ddns.net/?token=...`.
8. Frontend подхватывает токен и авторизует пользователя.

## 3. Сбор и обработка данных (Collector + Brain)

SaaS-решение Table AI переносит концепцию «AI Конструктора» из Google Sheets в современный веб-интерфейс.

### 📤 Коллектор (Collector)
- **VK/Telegram Import:** Загрузка массива постов по ссылке или ID. Воркер создает запись в `imports` и наполняет таблицу `content`.
- **Manual Input (Reviews):** Специальный режим для вставки отзывов или любого текста вручную. Текст сохраняется как объект `content` с метаданными источника.
- **OCR Vision Import:** Загрузка изображения (скриншота). Воркер использует Gemini 1.5 Flash Vision для извлечения текста и автоматически сохраняет его как отзыв.
- **Группировка:** Все загруженные данные связываются через `import_id`, что позволяет отслеживать историю и контекст каждой операции.

### 🧬 Пакетный Анализ и Цепочки (Batch & Chains)
SaaS-решение поддерживает два режима работы с AI:
1. **Batch Analysis:** Агрегация нескольких постов в один большой контекст для разового анализа (экономия токенов).
2. **Prompt Chains:** Последовательное выполнение нескольких промптов. Результат шага 1 передается как `{{input}}` для шага 2. Это реализовано в `saas/backend/src/ai.ts` через функцию `executeChain`.

### 💰 Система Квот и Лимитов (Quotas)
Для контроля затрат на API внедрена система баланса:
- В таблице `users` поле `balance` хранит доступные "баллы".
- Middleware/Helper `checkQuota` в `index.ts` проверяет наличие баллов перед запросом.
- За каждый вызов Gemini (или шаг в цепочке) с баланса списывается 1 балл.
- Роль `admin` игнорирует проверку лимитов.

### 📊 Управление и Экспорт
- **Prompt Editor:** Интерфейс для CRUD-операций с таблицей `prompts`. Позволяет гибко настраивать системные инструкции без изменения кода.
- **Export System:** 
    - Clipboard API для быстрого копирования результатов.
    - Print-friendly CSS и JS-генератор окон для качественного сохранения отчетов в PDF.

### 📥 Коллектор (Collector)
- **VK/Telegram/Instagram Import:** Реальный скрапинг публичных данных без использования официальных API (через веб-превью и бриджи). Это позволяет избежать сложностей с получением разрешений от платформ.
- **Manual Input (Reviews):** Специальный режим для вставки отзывов или любого текста вручную. Текст сохраняется как объект `content` с метаданными источника.
- **OCR Vision Import:** Загрузка изображения (скриншота). Воркер использует Gemini 1.5 Flash Vision для извлечения текста и автоматически сохраняет его как отзыв.

## 4. Схема данных (Cloudflare D1)

- `users`: Профиль пользователя, роль (admin/user), баланс.
- `prompts`: Библиотека системных промптов (название, текст, описание).
- `imports`: Групповые операции загрузки контента.
- `content`: Сырые данные (тексты постов, отзывов), привязанные к импорту.
- `results`: Итоговые отчеты AI ("Распаковка"), связанные с набором входных данных.
