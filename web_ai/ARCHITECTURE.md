# Архитектура и Логика Проекта "Table AI" (Распаковка Эксперта)

## 1. Ключевая концепция: "Распаковка эксперта"

Основная цель проекта — предоставить экспертам (коучам, консультантам, блогерам) автоматизированный инструмент для глубокого анализа их собственной деятельности. Система помогает структурировать и "распаковать" их экспертизу, анализируя их цифровой след (посты в соцсетях, отзывы клиентов) с помощью AI.

Итоговый продукт — это не просто набор данных, а целостный, структурированный документ, который эксперт может использовать для построения личного бренда, создания контент-плана, понимания своей целевой аудитории и формулирования уникального торгового предложения.

## 2. Общий рабочий процесс (Workflow)

Процесс "распаковки" представляет собой конвейер, состоящий из следующих шагов:

1.  **Сбор данных**: Эксперт инициирует сбор своего контента. Система импортирует посты из социальных сетей и распознает текст с изображений (например, скриншотов отзывов). Эти сырые данные сохраняются в специальных листах Google Таблицы.
2.  **Автоматизированный анализ**: Пользователь запускает один из этапов "распаковки" через меню в Google Таблицах (например, "Обновить Презентацию", "Анализ ЦА").
3.  **Работа движка**: Система в фоновом режиме начинает пакетную обработку. Для каждой задачи она:
    а. Получает заранее созданный, специализированный **промпт с центрального сервера**.
    б. Собирает необходимые данные пользователя из ячеек таблицы.
    в. Отправляет объединенный запрос к AI (Gemini).
    г. Записывает полученный от AI результат в соответствующую ячейку на листе "Распаковка" или "ЦА".
4.  **Просмотр результатов**: После завершения анализа эксперт открывает "Просмотрщик Распаковки" — специальное окно с удобным интерфейсом, где все результаты представлены в виде структурированных, интерактивных карточек.
5.  **Экспорт в документ**: Из "Просмотрщика" эксперт может экспортировать все полученные инсайты в единый, красиво отформатированный Google Документ, который является финальным результатом всей "распаковки".

## 3. Компоненты системы (ключевые файлы из `/deploy`)

Система состоит из нескольких логических блоков, каждый из которых отвечает за свой этап конвейера.

### 3.1. Сбор данных (Источники)

Эти модули отвечают за наполнение таблиц сырым контентом для анализа.

*   `SocialImport.gs`: Отвечает за импорт постов из социальных сетей. Является ключевым поставщиком данных о контенте и стиле эксперта.
*   `ocrRunV2_client.gs`: Клиентская часть для запуска процесса распознавания текста (OCR) на изображениях. Позволяет эксперту "оцифровать" скриншоты отзывов клиентов, превращая их в текст для анализа.

### 3.2. Движок анализа (Бэкенд в Таблицах)

Это ядро системы, которое выполняет всю основную работу по анализу.

*   `CollectConfig.gs`: **Сборщик запросов**. Это **не** конструктор для пользователя. Его задача — программно подготовить данные для запроса к AI. Он берет **готовый промпт с сервера**, находит нужные данные пользователя в таблице и формирует единый запрос.
*   `reniewcell.gs`: **Движок автоматизации**. Это дирижер всего процесса. Он запускает пакетную обработку ячеек для каждого этапа распаковки ("Архетип", "Рефлексия" и т.д.). Управляет очередью, чтобы избежать превышения лимитов, автоматически повторяет неудачные запросы и пропускает ячейки, которые уже были успешно обновлены недавно.

### 3.3. Презентация и экспорт (Результат)

Этот блок отвечает за пользовательский опыт и представление финального результата.

*   `UnpackingViewer.gs`: Бэкенд-логика для "Просмотрщика". Собирает обработанные данные из листов "Распаковка" и "ЦА". Главная функция — `exportUnpackingToDoc()`, которая создает финальный Google Документ.
*   `UnpackingViewerUI.html`: Пользовательский интерфейс "Просмотрщика". Отображает результаты в виде интерактивных карточек и предоставляет кнопки для управления и экспорта. Это "витрина" сервиса, которая делает результаты понятными и полезными.

### 3.4. Управление и инфраструктура

Эти файлы обеспечивают работу всей системы, связывая компоненты и контролируя доступ.

*   `Main.gs`: **Точка входа**. Создает пользовательское меню в Google Таблицах, из которого запускаются все процессы: импорт, анализ, просмотр результатов.
*   `server.gs`: **Серверный API**. Служит единой точкой входа для всех запросов с клиентской части. Проксирует запросы к Gemini, обрабатывает запросы на OTA-обновления и взаимодействует с модулем лицензирования.
*   `license.gs`: **Модуль лицензирования**. Инкапсулирует всю логику, связанную с проверкой лицензий, промокодов и уровней доступа.

## 4. Поток данных (Data Flow)

1.  **Начало**: Посты из соцсетей и текст с картинок-отзывов.
2.  **Шаг 1**: Данные сохраняются в сыром виде в ячейках **Google Sheets**.
3.  **Шаг 2**: `reniewcell.gs` и `CollectConfig.gs` используют эти данные и серверные промпты для запросов к **Gemini AI**.
4.  **Шаг 3**: Результаты анализа записываются в другие ячейки на листах "Распаковка" и "ЦА".
5.  **Шаг 4**: `UnpackingViewer.gs` читает эти обработанные ячейки.
6.  **Шаг 5**: `UnpackingViewerUI.html` отображает их в виде карточек.
7.  **Конец**: Данные экспортируются в структурированный **Google Документ**.

## 5. Путь пользователя (User Journey)

1.  Пользователь открывает свою Google Таблицу.
2.  Через меню "Table AI" запускает `SocialImport` для загрузки постов.
3.  Загружает скриншоты отзывов и через меню запускает `OCR`.
4.  После сбора данных, пользователь через то же меню запускает один из этапов распаковки, например, "🎯 обновить Архетип".
5.  Система в фоновом режиме выполняет анализ. Пользователь может продолжать работать с таблицей.
6.  По завершении, пользователь открывает меню "📦 Просмотр Распаковки".
7.  В появившемся окне он изучает полученные инсайты.
8.  Нажимает "Экспорт в документ", чтобы получить финальный артефакт своей "распаковки".
